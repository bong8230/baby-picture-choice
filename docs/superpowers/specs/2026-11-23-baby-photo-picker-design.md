# 아기 앨범 사진 고르기 — 설계

작성일: 2026-11-23 (주차별 부부 투표 방식으로 개정)

## 의도

갤럭시 휴대폰의 아기 사진 중 매주 1~3장을 골라 앨범 업체에 보낸다.
사용자는 비슷하게 잘 나온 사진 사이에서 고르기를 어려워한다(선택장애).
날짜별로 고르기에는 양이 너무 많아서 주 단위로 한다.

방식은 다음과 같다.
1. 사용자가 그 주의 괜찮은 사진을 대충 추려 올린다.
2. 사용자와 아내가 각자 휴대폰에서 토너먼트로 투표한다.
3. 두 사람이 모두 3위 안에 넣은 사진을 저장한다.

고르는 부담을 줄이는 동시에, 부부가 함께하는 작은 이벤트가 되는 것이 목적이다.

## 목표

- 사용자가 주차별 후보 사진을 올린다. 앱이 흐린 사진과 거의 같은 사진을 자동으로 거른다.
- 각자 휴대폰에서 두 장씩 고르는 토너먼트로 1~3위를 정한다. 상대 결과는 둘 다 끝날 때까지 숨긴다.
- 두 결과를 합쳐 주당 1~3장을 정한다. 원본을 PC `selected/`에 저장한다.
- 아내는 링크만 받아서 아무것도 설치하지 않고 투표한다.

## 비목표

- 휴대폰 앨범에 직접 쓰기, 회원가입이나 로그인
- 사진 편집이나 보정, 동영상 처리
- 앨범 레이아웃이나 업체 전송
- 날짜별 자동 고르기 (이전 안이었으나 폐기)

## 반목표 (동작해도 실패인 경우)

- 저장된 사진이 재압축·리사이즈되어 인화 화질이 떨어진다.
- 사진이 이 PC와 두 휴대폰 밖(클라우드, CDN)에 저장된다.
- 투표 링크를 모르는 사람이 사진을 보거나, 관리 기능을 쓸 수 있다.
- 투표 기간이 아닌데 외부에서 접속할 수 있다.

## 제약

- 휴대폰: 갤럭시(본인), 아내 휴대폰(기종 미정, 최신 Chrome 또는 Safari 가정).
- PC: Windows 11, Node v24, Tailscale 1.104.6(`my-pc.example-tailnet.ts.net`).
- 본인 갤럭시에는 Tailscale이 있다. 아내는 Tailscale을 쓰지 않는다.
- 공유기 내부 IP가 없다. 외부 접속은 Tailscale Funnel로만 한다.
- 포트 8787은 다른 프로그램이 쓰고 있다. 이 앱은 `127.0.0.1:8790`을 쓴다.
- 기존 Tailscale serve 설정(443 → 18951, 8443 → 8787)은 건드리지 않는다. 443과 8443에 Funnel을 켜면 그 서비스들까지 공개되므로 쓰지 않는다. 이 앱은 **10000 포트**를 쓴다.
- Chrome Android는 HEIC를 디코딩하지 못한다. 갤럭시 기본 설정은 JPEG이다.

## 접근 방식

**호스팅**

1. **Tailscale Funnel (선택)**: PC 서버를 공개 https 주소로 연다. 사진은 PC에만 있다. https 덕분에 secure context 문제도 없다. PC가 켜져 있어야 한다.
2. 클라우드 저장소: 사진이 외부에 나가므로 반목표에 어긋난다.
3. 공인 IP 포트 개방: 보안이 약하고 설정이 번거롭다.

사용자는 1을 골랐다. Funnel은 투표 기간에만 켜고 끈다.

**두 사람 결과 합치기**

1. 순위 점수 합산(1위 3점, 2위 2점, 3위 1점)
2. **둘 다 고른 사진 우선 (선택)**: 두 사람이 모두 3위 안에 넣은 사진만 저장한다.

사용자는 2를 골랐고, 주당 저장 수는 1~3장이다.

## 전체 흐름

```
[본인 갤럭시 · tailnet]                [PC Node 서버 127.0.0.1:8790]
 1. 주차 후보 올리기 ── 분석 후 원본 업로드 ──▶ pool/2026-W47/
 2. "투표 시작" ─────────────────────────────▶ 투표 토큰 생성, 링크 표시
    PC에서 npm run funnel:on  (10000 포트 공개)
 3. 본인·아내 각자 링크 → 토너먼트 ─ 투표 ─────▶ data/weeks/2026-W47.json
 4. 둘 다 끝나면 결과 공개 ─ 겹친 사진 ─────────▶ selected/2026-W47_1.jpg ...
    PC에서 npm run funnel:off
```

## 세부 동작

### 1. 후보 올리기 (본인, 관리 화면)

- tailnet 주소 `https://my-pc.example-tailnet.ts.net:10000/admin`으로 접속한다.
- 갤러리에서 사진을 여러 장 고른다. EXIF `DateTimeOriginal`로 ISO 주차(`2026-W47`)를 계산한다. EXIF가 없으면 `file.lastModified`를 쓴다.
  여러 주가 섞여 있으면 주차별로 나눠 보여준다.
- 휴대폰에서 `analyzeDay(files)`(아래)를 돌린다. 흐림과 중복으로 걸러진 사진을 보여주고, 사용자가 되살릴 수 있다.
- 확정한 사진의 **원본 바이트를 그대로** `pool/<주차>/`에 업로드한다. 재인코딩하지 않는다.
  화면 표시용 썸네일(긴 변 1600px 정도)은 서버가 아니라 휴대폰에서 만들어 함께 올린다. 투표 화면은 썸네일을 쓴다.
- 이미 사진이 있는 주에 더 올리면 추가된다. 투표가 시작된 주에는 추가할 수 없다.
- 후보는 8~16장을 권장한다. 32장을 넘으면 경고한다.

### 2. 투표 시작과 Funnel

- 관리 화면의 "투표 시작"은 그 주를 `voting` 상태로 바꾼다. 추측할 수 없는 투표 토큰(128비트 이상, URL-safe)을 만든다.
- 투표 링크는 `https://my-pc.example-tailnet.ts.net:10000/v/<토큰>` 형식이다. 화면에 복사 버튼을 둔다.
- `npm run funnel:on`은 10000 포트를 공개(Funnel)로, `npm run funnel:off`는 tailnet 전용(serve)으로 되돌린다.
  - 평소: `tailscale serve --bg --https=10000 http://127.0.0.1:8790`
  - 투표 중: `tailscale funnel --bg --https=10000 http://127.0.0.1:8790`
  - 다른 포트의 serve 설정은 바꾸지 않는다. 스크립트 실행 후 `tailscale funnel status`를 출력한다.
- 관리 화면에 현재 Funnel 상태를 보여준다. 결과가 확정되면 "이제 funnel:off 하세요"라고 안내한다.

### 3. 접근 제어

- Funnel로 들어온 요청(헤더 `Tailscale-Funnel-Request: ?1`)은 `/v/<유효한 투표 토큰>`과 그 하위 API, 투표 화면용 정적 파일(`/vote.*`, `/bracket.js`, `/styles.css`)만 허용한다. 나머지는 404를 반환한다.
  Tailscale 1.104.6은 클라이언트가 보낸 이 헤더를 지우고, 실제 Funnel 요청에만 붙인다(Codex 확인).
- 관리 화면과 업로드 API는 헤더 부재만으로 열지 않는다. Funnel 요청이 아니고, `Tailscale-User-Login`이 본인 계정과 일치할 때만 허용한다.
  허용할 계정은 설정 파일(`config.json`, gitignore 대상)에 둔다.
- 투표 토큰은 **투표자별로 하나씩** 발급한다(나, 아내). 서버가 토큰으로 역할을 고정한다. 링크에서 "나 / 아내"를 고르는 단계는 없다.
- `npm run funnel:off`는 `done` 상태인 주의 투표 토큰을 폐기한다. 다음 주에 Funnel을 다시 켜도 지난 사진은 열리지 않는다. (Claude 결정)
- 토큰이 틀리거나 그 주가 `voting` 또는 `done` 상태가 아니면 404를 반환한다. 존재 여부를 드러내지 않는다.
- 사진 파일은 토큰 경로 아래에서만 제공한다(`/v/<토큰>/img/<id>`). `pool/` 경로를 직접 노출하지 않는다.
- 구현 첫 단계에서 Funnel 요청에 이 헤더가 실제로 붙는지 확인한다.

### 4. 토너먼트 (각자)

- 각자 자기 링크로 들어온다. 한 사람당 한 번만 투표하고, 서버에 각자 진행 상태를 저장한다.
- 대진은 사람마다 무작위로 섞는다. 후보 수가 2의 거듭제곱이 아니면 1회전에 부전승을 둔다.
- 한 판은 두 장을 세로 화면 위아래로 크게 보여준다. 더 좋은 쪽을 탭한다. "8강 2/4" 같은 진행 표시와 직전 선택 되돌리기를 둔다.
- 순위: 우승 1위, 결승 패자 2위, 준결승 패자끼리 3·4위전을 해서 이긴 쪽이 3위다. 후보가 3장 미만이면 있는 만큼만 순위를 매긴다.
- 중간에 나가도 서버 상태로 이어서 한다.
- 끝나면 "상대를 기다리는 중" 화면이 나온다. 상대의 진행 여부(끝났는지)만 보여주고, 상대의 선택은 숨긴다.

### 5. 결과 합치기와 저장

- 둘 다 끝나면 결과를 계산한다.
  - 두 사람이 모두 3위 안에 넣은 사진만 저장 대상이다. 겹친 수만큼 1~3장이 된다.
  - 순서는 두 사람 순위 합이 작은 순서다. 같으면 `analyze` 점수가 높은 쪽이 앞이다.
  - 겹친 사진이 없으면 **함께 결승**을 한다. 두 사람 각자의 1위 사진으로 한 판을 하고, 먼저 탭한 쪽(둘이 상의해서)으로 1장을 정한다. 둘 중 누구의 화면에서 해도 된다.
- 결과 화면은 두 사람 모두 볼 수 있다. 각자의 1~3위, 겹친 사진, 최종 저장 사진을 보여준다. 이벤트답게 결과 공개 연출을 넣는다.
- 확정 시 원본을 `selected/<주차>_<순위>.<확장자>`로 복사한다(예: `selected/2026-W47_1.jpg`). 그 주는 `done` 상태가 된다.

### 데이터

- `pool/<주차>/<id>.<ext>` 원본, `pool/<주차>/<id>.thumb.jpg` 썸네일
- `data/weeks/<주차>.json`: 상태(`collecting` | `voting` | `done`), 투표 토큰, 사진 목록(id, 원래 파일명, 촬영 시각, 점수), 투표자별 대진·진행·순위, 최종 결과
- 주차별로 읽기·검증·수정·저장 전체를 직렬화한다(주차별 비동기 잠금). 파일 쓰기는 임시 파일에 쓴 뒤 rename한다.
- 투표와 되돌리기 요청에는 현재 경기 ID를 담는다. 서버 상태와 다르면 거부하고 최신 상태를 돌려준다. 함께 결승은 서버가 처음 수락한 유효 요청만 반영한다.
- 최종 저장은 두 단계로 한다. 먼저 저장할 사진과 파일명을 JSON에 기록한다(`finalizing`). 그다음 복사한다. 서버가 재시작되면 같은 파일명으로 이어서 복사한다. 모두 성공했을 때 `done`으로 바꾼다.
- `pool/`, `data/`, `selected/`는 `.gitignore`에 넣는다.

## 분석 모듈 `public/analyze.js` (Codex 담당)

용도: 1단계 후보 거르기, 중복 묶음의 대표 고르기, 결과 동점 처리.

```js
export async function analyzeDay(files, { onProgress } = {})
// onProgress({ done: number, total: number })
// → { kept:     [{ file, score, reasons: string[] }],   // 점수 내림차순
//     excluded: [{ file, score, reason: 'blur' | 'duplicate' | 'unsupported', duplicateOf?: File }],
//     warnings: string[] }   // 예: 'face-model-unavailable'
```

- 주차별로 한 번 호출한다. `onProgress`의 `done`에는 디코딩 실패도 포함한다.
- `unsupported`의 `score`는 `null`이다. `duplicateOf`는 최종 `kept`에 있는 대표 `File`이다.
- 같은 주에 사진을 나중에 추가하면, 기존 후보와 새 사진을 함께 다시 분석한다. 점수가 한 배치 기준으로 맞춰지게 하기 위해서다. 화면은 기존 원본 대신 서버의 썸네일을 넣는다. (Claude 결정)
- 각 사진을 긴 변 512px 정도로 축소해 분석한다. 원본 `File`은 건드리지 않는다.
- 흐림: 그레이스케일 Laplacian 분산. 그 묶음 안에서 상대적으로 낮은 사진을 제외한다.
- 중복: dHash 해밍 거리로 묶는다. 묶음마다 점수가 가장 높은 1장만 남긴다. 연사에서 눈 감은 컷을 빼는 데 얼굴 점수가 쓰인다.
- 얼굴: MediaPipe Tasks Vision Face Landmarker(blendshapes).
  - **사진 속 모든 얼굴을 반영한다(사용자 결정).** 누구든 눈을 감았으면 감점하고, 미소는 가장 잘 웃는 얼굴 값을 쓴다.
    "모든 얼굴"은 모델이 검출한 얼굴 기준이다. `numFaces` 상한은 5로 한다.
  - **얼굴 점수는 약하게 반영한다(사용자 결정).** 선명도와 노출이 주가 된다.
  - 얼굴이 없는 사진은 얼굴 항목을 빼고 다시 정규화해서, 불이익이 없게 한다.
- 디코딩할 수 없는 파일(HEIC 등)은 `unsupported`로 제외한다.
- 모델 초기화나 추론이 실패하면 얼굴 점수 없이 계속하고 `warnings`에 사유를 넣는다.
- 사진 사이마다 이벤트 루프에 양보해 진행 표시가 멈추지 않게 한다.
- 모델과 wasm은 `public/vendor/mediapipe/`에 버전을 고정해 두고 로컬에서 제공한다. CDN은 쓰지 않는다.
  서버는 `.js`와 `.mjs`에 `text/javascript`를, `.wasm`에 `application/wasm`을 반환한다.
- 목표: 50장 기준 갤럭시에서 10초 이내. 첫 모델 로드 시간은 포함하지 않는다.

## 구현 첫 단계 (검증 스파이크)

1. 10000 포트 serve와 funnel을 켜고 끈다. 전환 전·후·복귀 후 `tailscale serve status --json`을 비교해 443과 8443 매핑이 그대로인지 확인한다.
   상태 표시는 명령 성공 여부가 아니라 실제 설정을 읽어서 한다.
2. 휴대폰 데이터망(Wi-Fi 끔)으로 Funnel 주소에 접속해 `Tailscale-Funnel-Request` 헤더를 확인한다.
   위조 헤더를 보내도 `/admin`과 업로드 API가 404인지 확인한다. off 뒤에는 외부 접속이 끊기는지 확인한다.
3. 갤럭시에서 MediaPipe 얼굴 1장의 blendshape 출력을 확인한다.

셋 중 하나라도 안 되면 다음 단계로 가지 않고 사용자와 상의한다.
tailnet ACL에서 Funnel이 꺼져 있으면, 관리 콘솔 설정은 사용자가 직접 한다.

## 빌더에게 맡기는 것

- 점수 가중치와 흐림·중복 기준의 구체 값
- 화면의 세부 디자인과 결과 공개 연출(휴대폰 세로 화면, 큰 탭 영역 전제)
- 썸네일 크기와 품질

## 개정 2026-11-24: HEIC 지원 (사용자 결정 (c))

사용자의 갤럭시 카메라는 HEIC로 저장한다. Chrome Android는 HEIC를 디코딩하지 못한다.

- 휴대폰에서 libheif(WASM, `public/vendor/libheif/`, 버전 고정, CDN 없음)로 HEIC를 디코딩한다. 디코딩한 이미지로 분석과 썸네일을 만든다.
- HEIC 사진은 원본 해상도의 JPG(품질 0.95)를 휴대폰에서 한 번 만든다. 업로드는 썸네일, 원본 HEIC, 변환 JPG를 함께 보낸다.
- `pool/<주차>/`에는 원본 HEIC와 `<id>.full.jpg`를 보관한다.
- 최종 저장: `selected/`에는 항상 `.jpg`만 저장한다. JPG 원본은 바이트 그대로 복사하고, HEIC 사진은 `<id>.full.jpg`를 복사한다.
- 원칙 변경: "재압축 금지"는 JPG 원본에 대해서만 유지한다. HEIC 원본은 보관하고, 업체용으로만 JPG로 한 번 변환한다.
- 변환 JPG에는 EXIF가 없다(사용자에게 안내함, 파일명에 주차·순위가 있음).
